Our next task is to implement a ros2 node which republishes the ros2 topic /ground_truth/odom into /odom and publishes odom->base_link to the transform tree. This node should optionally (default true) publish a static identity transform from map to odom. This will allow a full transform tree (minus the robot - that is later) to be present in the ros2 system being served by the simulation launched from bringup/launch_tractor.py. This should be a fast node, so we shall chose c++, and this node should be present in the directory src/ground_truth_localization. You can use the example in ../ugv_ws/src/ground_truth_republish as a similar example - although note that /ground_truth/odom is a true odom message, not a pose which needs to be differences. This ros2 node should use the system ros2 humble, which evolves from source /opt/ros/humble/setup.bash. ROS2 dev and builds for code in src/ should not use the ros2 implied by the use of the conda env isaacsim61-cu13. So shell usage should be kept separate. This new c++ node should expose parameters like the example given in ground_truth_republish. When run in conjuction with the launched simulator (bringup/launch_tractor.py), this new node should populate the tf tree and the new topics (/odom).

This node will need a launch file which accepts/sets the default names for frames and topics. This is general purpose node for simulators which provide ground truth (as an odometry message).
